# AI Builder — منصة بناء المواقع والتطبيقات بالذكاء الاصطناعي

واجهة عربية RTL لتوليد نماذج ويب ومشاريع أولية متعددة الملفات عبر مزود ذكاء اصطناعي.

## التشغيل
يتطلب Node.js 22+:
```bash
cp .env.example .env.local
npm install
npm run dev
```
ثم افتح http://localhost:3000.

## تفعيل التوليد
اضبط `AI_PROVIDER` على `openai` أو `anthropic` أو `google`، ثم أضف المفتاح الموافق في بيئة الخادم. أسماء المتغيرات موجودة في `.env.example`. لا تستخدم `NEXT_PUBLIC_*` للأسرار ولا ترفع `.env.local` إلى GitHub.

## ما يعمل في هذا الإصدار
- واجهة عربية متجاوبة.
- مسار خادمي `/api/generate` لتوليد نموذج HTML واحد وتنزيله.
- مسار `/api/generate-project` لتوليد ملفات أولية متعددة لمشروع Vite + React + TypeScript.
- فحوص لمسارات الملفات المولدة لمنع المسارات المطلقة و`..` والشرطات العكسية، مع حدود لعدد الملفات وحجم كل ملف والحجم الإجمالي.
- فحص `package.json` المولد ورفض سكربتات دورة حياة npm وسكربتات `pre*` و`post*` وأوامر npm غير المدرجة ضمن أوامر Vite/TypeScript المعروفة ومصادر التبعيات المباشرة من URL/Git/مسارات محلية أو npm aliases؛ ما زال يلزم مراجعة أسماء الحزم العادية ومحتوى الملفات قبل تثبيتها أو تشغيلها.
- تنزيل ملفات المشروع المتعددة كأرشيف ZIP وعرض محتوى كل ملف في الواجهة.
- نسخ محتوى الملف المحدد من محرر الكود.
- معاينة HTML الثابت داخل iframe معزول دون منح JavaScript صلاحية التشغيل.
- حفظ آخر مساحة عمل تلقائيًا محليًا في المتصفح واستعادتها عند إعادة فتح الصفحة.
- حفظ وإعادة فتح وحذف حتى 20 مساحة عمل من قائمة «مشاريعي المحفوظة»؛ القائمة محفوظة في `localStorage` على نفس المتصفح والجهاز، وليست مزامنة سحابية أو نسخة احتياطية.
- فحوص حجم الطلب ومصدر المتصفح وحدّ طلبات مؤقت على مستوى العملية.
- مفاتيح المزود تبقى على الخادم ورسائل الأخطاء لا تعرض الأسرار.
- نقطة فحص صحة `/api/health` تعرض حالة الخدمة ومؤشر إعداد المزود فقط، دون إرجاع قيم المفاتيح؛ ويستخدمها فحص Docker.

## حدود مهمة
هذه نسخة MVP وليست منشئ تطبيقات متكاملًا بعد. تُنزّل الملفات المولدة في أرشيف ZIP، لكن ذلك لا يعني أن المشروع اجتاز البناء أو الاختبارات أو المراجعة الأمنية. لا توجد حتى الآن مصادقة أو حفظ مشاريع في قاعدة بيانات أو معاينة معزولة لمشاريع React متعددة الملفات أو تشغيل آمن للكود أو نشر تلقائي. نقطة `/api/health` فحص حيوية بسيط وليست فحصًا عميقًا لاتصال مزود الذكاء الاصطناعي. معاينة HTML الثابت تعمل داخل iframe بلا صلاحية JavaScript، وهي ليست بيئة تشغيل كاملة ولا ضمانًا أمنيًا مطلقًا. آخر مساحة عمل وقائمة المشاريع المحفوظة تبقيان محليًا في المتصفح فقط، ولا تنتقلان بين الأجهزة أو المتصفحات ويمكن أن تُحذفا عند مسح بيانات المتصفح. لا تفتح أو تشغّل الملفات المولدة قبل مراجعتها. فحص سكربتات npm دفاع إضافي وليس ضمانًا بأن محتوى JavaScript أو التبعيات آمنة.

محددات الطلبات الحالية محلية لكل عملية فقط، وقد لا تحمي تطبيقًا موزعًا أو serverless. عند `TRUST_PROXY_HEADERS=false` يستخدم المساران مفتاحًا احتياطيًا واحدًا، لذلك تتشارك كل الزيارات حد الطلبات على نفس العملية وقد يتأثر المستخدمون ببعضهم؛ هذا سلوك محافظ وليس تحديدًا عادلًا لكل مستخدم. لا تفعّل `TRUST_PROXY_HEADERS=true` إلا إذا كان وكيل موثوق يزيل الرؤوس الواردة من العميل ويكتب `x-real-ip` أو `x-forwarded-for` بنفسه. قبل إتاحة الخدمة للعامة، استخدم محدد طلبات مشتركًا مثل Redis أو حماية على مستوى الاستضافة، واضبط هوية العميل من إعداد موثوق. لا تعتمد على رؤوس IP التي يرسلها العميل مباشرة.

## تشغيل الإنتاج عبر Docker

يتطلب Docker Engine وDocker Compose. انسخ ملف البيئة النموذجي ثم ضع مفتاح مزود واحدًا على الأقل في `.env.local`:

```bash
cp .env.example .env.local
# عدّل .env.local وأضف مفتاح المزود الذي اخترته
docker compose up --build -d
docker compose ps
docker compose logs -f ai-builder
```

تتوفر الخدمة افتراضيًا على `127.0.0.1:3000` فقط؛ ضع وكيل HTTPS عكسيًا موثوقًا أمامها عند الحاجة للوصول الخارجي، ولا تفتح منفذ التطبيق مباشرة للإنترنت. يفترض Compose وجود `.env.local`؛ لا ترفعه إلى Git. للإيقاف: `docker compose down`. ملف Docker الحالي يبني التطبيق ويحتفظ بتبعيات البناء في الصورة النهائية، لذا خطّط لتحسين حجم الصورة قبل تشغيل إنتاج واسع النطاق.

## الفحوص الآلية

يشغّل GitHub Actions فحوص TypeScript والاختبارات وESLint وبناء Next.js، ثم يبني صورة Docker للتحقق من ملف الحاوية. نجاح هذه الفحوص لا يغني عن مراجعة الثغرات والتبعيات أو اختبار التشغيل الفعلي في بيئة النشر. وجود خطوة في سير العمل لا يعني نجاحها؛ راجع تبويب **Actions** في GitHub للتأكد من نتيجة آخر تشغيل قبل اعتبار النسخة جاهزة للنشر.

## النشر
اربط المستودع بمضيف يدعم Next.js واضبط متغيرات البيئة من لوحة الاستضافة. لا تضع مفاتيح API في المستودع أو ملفات العميل.

### HTML output handling

The HTML preview and download actions share the tested `src/lib/html-output.ts` extractor. It only accepts an explicit fenced `html` block; it does not guess that arbitrary model text is a document. The preview remains inside a sandboxed iframe with no script permission. Unit tests live in `src/lib/html-output.test.ts` and run with `npm test`.
